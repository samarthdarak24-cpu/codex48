**Key architectural decisions (keep these if work resumes):**
- `services/api.ts` is the ONLY data seam. No component imports demo data directly.
- `lib/selectors.ts` computes every dashboard metric from records — no hardcoded numbers anywhere.
- `lib/ruleEngine.ts` is a deterministic, dependency-free rule engine (text rules + asset-fact rules).
  Unknown evidence → "Needs Review", never a false pass/fail. It is the client mirror of the future
  `app/services/rule_engine.py`.
- `context/DataContext.tsx` holds the working set and all mutations (mirrors the future API surface).
- `services/demoStore.ts` is a TEMPORARY sessionStorage cache so reloads/role switches keep mutations.
  Delete it when the FastAPI backend lands.
- `lib/demo-data.ts` is an isolated fictional dataset; sidebar labels it "Fictional demo workspace".
